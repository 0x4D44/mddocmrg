## Summary
The current code coverage is low because the CLI entry point (`main`) and usage instructions (`print_usage`) are not tested. The core logic functions (`extract_text_from_docx`, `merge_docx_files`) have good coverage, but error paths are missed.

    *   **0% Coverage.** Never called.

## Missing Coverage Areas
1.  **CLI Argument Parsing:** No tests verify that `-s` sets the flag or that `-h` prints help.
2.  **Program Entry:** `main` is untested.
3.  **Usage Output:** `print_usage` is untested.
4.  **Error Propagation:** Specific error branches in XML parsing are not triggered.

## Recommendations
1.  Refactor `main` to extract the CLI logic into a testable function (e.g., `run(args: Vec<String>)`).
2.  Replace `std::process::exit` in the logic with return values to allow testing assertions.
3.  Add integration tests that simulate command-line execution.
